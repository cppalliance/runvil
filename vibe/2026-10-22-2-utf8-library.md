# utf8 library and compactor

<product-contract>

## Product Requirements

Lua code in Runvil's sandbox cannot call Lua's standard `utf8` library today, so authors can only cut strings by byte, and a byte cut in the chat agent's compactor once made every later chat turn fail silently. This plan loads `utf8` into every section VM and Pack prelude, switches the compactor's excerpt cut to `utf8.offset`, and documents `utf8` in the language guide. The work is two `runvil` commits on PR #166 and one `runvil-docs` commit.

- Problem and users:
  - Users are prompt authors writing Lua blocks, Pack prelude authors, and the chat agent, whose compactor summarizes older turns when a turn overflows the model's context.
  - The sandbox loads only `StdLib::STRING | StdLib::TABLE | StdLib::MATH` (`crates/runvil-internal/lua/src/vm.rs` line 258, `crates/runvil-internal/lua/src/program.rs` line 20), so `utf8` reads nil, and the guide lists it among the names that read nil (`src/language/05-lua-environment.md` line 559).
  - Commit `8e5248059` ("Cut chat summary excerpts on UTF-8 character boundaries") fixed a bug where the compactor's byte slice `:sub(1, 1500)` split a multibyte character and made the summary prompt invalid UTF-8. `models.infer` refused that prompt, compaction restored the records, and the agent's `pcall` swallowed the error, so every later turn failed silently. Because `utf8.offset` was unavailable, that fix walks back over continuation bytes by hand (`crates/workshop/agents/agents/chat.md` lines 45-54).
- Goals:
  - Prompt code and Pack prelude code can call Lua 5.5's standard `utf8` library: `utf8.char`, `utf8.charpattern`, `utf8.codes`, `utf8.codepoint`, `utf8.len`, and `utf8.offset`.
  - The chat agent's compactor cuts each summary excerpt with `utf8.offset` instead of its hand-written walk over continuation bytes.
  - The language guide documents `utf8` and stops saying it reads nil.
- Non-goals:
  - No other standard library is added. `coroutine`, `io`, `os`, `package`, and `debug` stay absent (`crates/runvil-internal/lua/src/hardening.rs` lines 23-25).
  - The guide's teaching example of the summarizing compactor (`src/language/11-conversations.md` lines 2419-2443), which has no excerpt cut, stays as it is.
  - The parser, the `_G` guard, and the `runvil` facade API do not change.
- Success criteria:

  - The existing multibyte compactor tests pass unchanged.
  - Every exit gate in the Testing Plan passes after each `runvil` commit, and the guide checks and site build pass after the `runvil-docs` commit.

## Functional Specification

`utf8` becomes a standard-library global wherever `string` is one: every section VM, the H1 pass, and every Pack prelude's environment. It is reserved like the other kept Lua globals and behaves exactly as Lua 5.5 defines it. The chat compactor's excerpt keeps today's cut, now computed by `utf8.offset`.

- Actors and workflows:
  - A prompt author calls `utf8.*` from any Lua block, in any section and in the H1 pass.
  - A Pack prelude author calls `utf8.*` from prelude code and from prelude functions that author code calls later.
  - On a context overflow, the chat agent's compactor builds a summary prompt from a capped excerpt of each older record, cut with `utf8.offset`.
- Inputs and outputs:
  - Lua 5.5's `utf8.offset(s, n [, i])` returns two values, the start and the end byte of the character. With `n = 0` it returns the character that holds byte `i`, and it does not raise when byte `i` is a continuation byte. Lua 5.4 returned only the start. (Source: `byteoffset` in `lutf8lib.c`, lines 178-224 of the `lua-5.5.0` copy in the `lua-src` 550.1.1 crate; the `lua-5.4.8` copy returns one value.)
  - `utf8.len` returns fail and the position of the first invalid byte on invalid UTF-8.
  - Positions in every `utf8` function are byte positions, as in `string`.
  - The compactor excerpt becomes, inside the record loop:

````lua
    local text = json.encode(messages[i].content)
    if #text > 1500 then text = text:sub(1, utf8.offset(text, 0, 1501) - 1) end
    local line = messages[i].role .. ": " .. text
````

  - The `- 1` keeps only `utf8.offset`'s first return value.
  - The cut is the same as today's: the excerpt ends before the character that holds byte 1,501.
- States and validation:
  - `utf8` is a reserved Lua global. A Pack prelude that defines a global named `utf8` fails with `` Pack `{pack}`: its prelude defines the global `utf8`, which is reserved as a Lua standard-library global `` (`crates/runvil-internal/lua/src/prelude.rs` line 186, `crates/runvil-internal/lua/src/globals.rs` line 194).
  - As with `string`, author code can still assign a global named `utf8`, because the `_G` guard covers only `argv`, `prose`, and `messages` (`crates/runvil-internal/lua/src/globals.rs` lines 1-27).
  - No prompt parses differently, because the parser's source never reads `RESERVED_NAMES`. Its only production reader is the prelude collision check (`crates/runvil-internal/lua/src/prelude.rs` line 186).
- Errors and recovery:
  - `utf8.offset` raises `position out of bounds` when `i` is outside `[1, #s + 1]`, so the compactor's `#text > 1500` guard is required: it keeps 1,501 inside that range.
  - The cut runs on `json.encode` output, which is valid UTF-8 because the encoder refuses strings that are not (`crates/runvil-internal/lua/src/json/encode.rs` lines 109 and 122), so the `n = 0` call does not raise inside the guard.
- Security and privacy behavior:
  - `utf8` is a pure library with no I/O and no way out of the VM, so loading it widens nothing an author can reach outside the VM.
  - The libraries that are never loaded stay unloaded (`crates/runvil-internal/lua/src/hardening.rs` lines 23-25), and scheduler-mode VMs still strip `coroutine` after the shim install (`crates/runvil-internal/lua/src/coro.rs` lines 124-128).
- Acceptance criteria:
  - In a section VM, `utf8.len('café') .. '|' .. ('café'):sub(1, utf8.offset('café', 0, 5) - 1) .. '|' .. utf8.char(233)` returns `4|caf|é`.
  - `reserved_name("utf8")` returns `Some(Reserved::LuaGlobal)`.
  - A prelude function sees `utf8` as a table.
  - Neither the chat agent nor its Engine test copy contains a `text:byte` walk, and the existing multibyte compactor tests pass unchanged.
  - The guide documents `utf8`, gives the new counts, and no longer lists `utf8` among the names that read nil.

## Technical Design

The change is one library flag in the Lua crate's two VM constructors, plus the bookkeeping that keeps `_G`, the reserved-name list, and the prelude environment in step. The compactor change is Lua text in the chat agent and its Engine test copy. No persisted data, protocol, or `runvil` facade API changes.

- Architecture:
  - `SectionVm::new` (`crates/runvil-internal/lua/src/vm.rs` lines 256-260) is the one constructor that every section VM, the H1 pass, `loop_scenario`, and the Lua-crate test VMs build through, so adding `StdLib::UTF8` there loads `utf8` everywhere author code runs.
  - The compile-only VM in `compile_chunk` (`crates/runvil-internal/lua/src/program.rs` lines 18-23) never runs code, but it loads the same set so the two lists stay identical.
  - A prelude's environment copies each name in `VISIBLE_GLOBALS` from `_G` when the prelude installs (`crates/runvil-internal/lua/src/prelude.rs` lines 31-53 and 108-113), so adding `"utf8"` there is what makes preludes see it.
- Modules and interfaces:
  - `RESERVED_NAMES` (`crates/runvil-internal/lua/src/globals.rs` line 207, re-exported at `crates/runvil-internal/lua/src/lib.rs` line 129) must match the globals a section VM installs. Two Engine tests enforce both directions, `every_global_section_setup_leaves_in_g_is_a_reserved_name` and `every_reserved_global_is_present_after_section_setup` (`crates/runvil-internal/engine/src/lua/tests/globals.rs` lines 107-141), so the load and the reservation land in the same commit.
  - `RESERVED_NAMES` is not part of the `runvil` facade, so `cargo xtask api --check` reports no change.
- File and public API changes:
  - `runvil_lua::RESERVED_NAMES` changes type from `[(&str, Reserved); 62]` to `[(&str, Reserved); 63]` and gains `("utf8", Reserved::LuaGlobal)`.
  - The private `VISIBLE_GLOBALS` changes type from `[&str; 20]` to `[&str; 21]`.
  - The chat agent's compactor (`crates/workshop/agents/agents/chat.md` lines 45-57) and its Engine test copy, the `COMPACT` constant (`crates/runvil-internal/engine/src/execute/tests/models_loop-author-shapes.rs` lines 41-66), drop the `excerpt` helper for the cut in the Functional Specification.
  - The line-level edits are listed under Execution Instructions.
- Data, persistence, failure, security, and privacy constraints:
  - No persisted data, protocol, or lifecycle changes.
  - The compactor's failure behavior is unchanged: the same cut and the same valid-UTF-8 summary prompt.
  - Only a pure library is added, as the Functional Specification's security behavior states.

## Decision Record

Vinnie set the scope and chose to land the `runvil` commits on PR #166. The remaining calls were made during planning and are reversible.

- Decisions:
  - Scope: load `utf8` in the Engine, document it in `runvil-docs`, and switch the compactor to the simple `utf8.offset` cut. Rationale: `utf8` is pure, and the hand-written walk exists only because the library was missing. Vinnie (2026-10-22): "lets add utf8 to the engine, add it to @runvil-docs docs, modify the compactor to use the utf8 simple version".
  - PR placement: the `runvil` commits go on local `master` and are pushed to `origin master`, which updates PR #166. Rationale: the compactor change belongs with the chat agent work already on that PR. Vinnie's chosen option: "Add it to #166 - the compactor change belongs with the chat agent work".
  - Pack preludes also see `utf8`. Rationale: it is pure, and prelude authors face the same byte-cutting problem. No user words; made during planning and reversible.
  - The compile-only VM in `crates/runvil-internal/lua/src/program.rs` loads the same set as `SectionVm::new`. Rationale: the two lists cannot drift apart. No user words; made during planning and reversible.
  - `stock_eval` (`crates/runvil-internal/lua/src/globals-tests.rs` lines 94-98), documented as a stock VM "with the section VM's standard libraries", also gains `StdLib::UTF8`. Rationale: its doc stays true. No user words; made during planning and reversible.
  - The library load and the compactor change are separate commits. Rationale: each commit's tests show what it changed. No user words; made during planning and reversible.
  - The new guide heading is ``### The `utf8` library``, matching ``### The `string` library`` and ``### The `math` library`` (`src/language/05-lua-environment.md` lines 430 and 524), and its quick-reference row links to the sandbox section as the `math`, `string`, and `table` rows do (`src/language/17-quick-reference.md` lines 106, 179, and 189). Rationale: consistency with the neighboring entries. No user words; made during planning and reversible.
- Rejected alternatives:
  - Keeping the hand-written walk over continuation bytes. Reason: `utf8.offset` makes the same cut in one call that every Lua author knows. Revisit if `utf8` is ever removed from the sandbox.
  - Loading `utf8` in section VMs but hiding it from preludes. Reason: preludes face the same problem, and the library is pure. Revisit if the prelude environment must shrink for another reason.
  - Landing the load and the reservation in separate commits. Reason: the two Engine guards in `crates/runvil-internal/engine/src/lua/tests/globals.rs` would fail on the commit between them. Revisit if those guards change.
- Assumptions, risks, and notes:
  - Risk: Lua 5.5's two-value `utf8.offset` differs from Lua 5.4's single value, so the guide says so, and code that uses the call as the last argument of another call passes both values unless it adjusts the result, as the `- 1` does.
  - Risk: author code that assigns a global named `utf8` overwrites the library for the rest of that VM, exactly as with `string`.
  - Assumption: mdBook is installed for the site build; the build runs the program named by `MDBOOK`, or `mdbook` on `PATH` when it is unset (`crates/build-xtask/src/site.rs` lines 12 and 156).
  - Note: during planning, `runvil-docs` `e4937ed` was described as not yet pushed, while the local tracking ref `origin/master` (`git@github.com:cppalliance/runvil-docs.git`) also pointed at `e4937ed`. Either way, this plan pushes nothing in `runvil-docs`.
  - Note: `src/language/12-tools.md` lines 2621-2634 name the Lua standard-library globals only by example ("such as `string`, `pairs`, `_G`, and `_VERSION`"), and nothing in the Lua crate states the reserved-name count outside the array type, so neither needs a count change.
